Summary

A deterministic frailty measurement workflow with age-equivalent output withheld.

This repository implements a 35-variable input contract, an API-enforced Minimum Viable Vector (MVV), a deterministic Rockwood-style deficit-accumulation score, age/sex BIA z-score calibration, and a biological-age prediction interface that is currently withheld from output. It is a research prototype, not a diagnostic device. The shipped predictor is a deterministic integration fixture; no trained mortality model is included in this checkout.

Read this page as a review record. Each section links a claim to a measurement, a cited method, or an explicit missing approval. The status line and evidence gates describe the current boundary, not product validation.

Contract

The 35-feature contract

Every assessment request must reduce to the canonical 35-feature vector defined in src/frailty_engine/features.py. Anything outside that vector is rejected at the gateway with a ValidationError. Fitted model matrices have 36 columns: the 35 inputs (with sex one-hot as sex_male) plus the calculated FI.

Five categories, 35 variables — the complete canonical matrix.

Pipeline A

Deterministic Frailty Index (FI)

The FI follows the Rockwood accumulated-deficit construction (Searle et al., 2008): each measured variable is scored as 0, 0.5, or 1 against explicit, reviewable cutoffs; the score is the ratio of accumulated deficits to the count of validly measured FI-eligible variables. age and sex are excluded from scoring via FI_EXCLUDED_FEATURES = frozenset({"age", "sex"}).

Every numeric cutoff is annotated with its source string in src/frailty_engine/fi.py:CUTOFF_SOURCES. The repo's EVAL.md marks E-003 as passing for the denominator caveat and 0/0.5/1 coding. Sex stratification is wired (e.g. waist circumference, grip strength, creatinine) so subgroup analyses do not need code changes.

Where the FI's value comes from in practice

  • Auditability. Every cutoff maps to a a published or explicitly reviewable anchor (WHO BMI, ACC/AHA BP, ADA glycemia, KDIGO eGFR, EWGSOP2 grip, Sterling FIB-4, IDF waist). Some cutoffs remain engineering defaults pending target-cohort review; the list is intentionally short and easy to re-review.
  • No imputation. Missing values drop out of the denominator — they never get a score, and they are never replaced with a synthetic value. The denominator is exposed in every API response.
  • Population caveat. Cutoffs are not sex/age/ethnicity-validated in this checkout. They are explicit engineering defaults whose clinical claim must wait on external validation (E-005).

Calibration

BIA transfer calibration

Public NHANES 1999–2004 BIA measurements used a Xitron analyser; modern clinics use SECA mBCA. Training on raw values would bake hardware-specific drift into the model. The engine normalises every BIA input against a versioned ReferencePanel with age/sex bands: z = (value − band.mean) / band.sd.

Both training and inference paths consume the same z-scores, which is the practical value of the calibration step — device-era drift is stripped before the model ever sees the row.

Pipeline B

Age-equivalent output is intentionally withheld

The repository retains an age-equivalent development interface so integrations can exercise the schema. Its engineering defaults are not a fitted baseline curve, and the interface does not produce a result in this public review.

The code path stays visible because its constraints matter: the interface must not be relabeled as prognosis, mortality risk, or a treatment outcome. The public report therefore shows the withheld state rather than a persuasive-looking number.

The biological-age ci_95 field is nullable: the shipped predictor reports uncertainty_validated: false and ci_95: null. The adjacent uncertainty_construction: "none_withheld" label makes that withholding explicit. A numeric interval is reserved for an approved predictor with cohort-validated uncertainty, not a calibrated clinical confidence interval supplied by this fixture.

Caveat

Data quality & the denominator caveat

The FI is the ratio of accumulated deficits to the count of validly measured FI-eligible variables. That denominator is exposed on every response (metrics.current_deficit_load_fi_details), and it changes with measurement completeness. Two assessments of the same biology can yield different FI scores because one clinic measured 32 valid variables and another measured 28.

This is documented by design: it is the standard accumulated-deficit property called out in Searle et al. (2008). It is not a bug and it is not imputed around. It is a constraint on interpretation that downstream tooling must respect.

The API also supplies a count-only denominator band: low (0–18), moderate (19–27), or high (28–33). This is an engineering review label, not a clinical adequacy threshold or a patient target; always use the exact denominator and the caveat together. 

"data_quality": {
  "variables_measured": 32,
  "fi_variables_measured": 30,
  "mvv_passed": true,
  "blood_variables_measured": 9,
  "history_variables_measured": 6,
  "reference_panel_id": "seca-development-fixture",
  "reference_panel_sha256": "4a08b89976747925bb87cf9719224d59e0507a67a2187e3818102bf89cff9662",
  "reference_panel_production_ready": false,
  "reference_panel_fixture_only": true,
  "reference_panel_readiness": "development_fixture_only",
  "fi_denominator_strength": "high"
}

What this means for callers

  • Compare FI scores only across assessments with the same denominator count.
  • Treat trend lines that change denominator count as discontinuities, not drift.
  • Use data_quality.reference_panel_production_ready as a hard gate before persisting any score to a downstream clinical record.

Serving

Model & serving path

The local HTTP surface is a FastAPI app (src/frailty_engine/api.py) exposing GET /health, GET /readyz, and POST /v1/assessments. /health is liveness (HTTP 200 while the process responds; inspect its readiness.status body field); /readyz is the fail-closed deployment gate. The assessment pipeline (pipeline.py) parses, enforces MVV, runs the FI calculator, calls the BIA calibration, and routes to the active predictor. 

py -3 -m pip install -e ".[dev]"
py -3 -m pytest                        # repository test suite
py -3 -m frailty_engine sample         # CLI sample assessment
py -3 -m uvicorn frailty_engine.api:app --app-dir src

# Locked alternative: uv sync --locked --extra dev
uv run uvicorn frailty_engine.api:app

The development predictor is a deterministic integration fixture; it does not represent a fitted mortality model. A trained XGBoost survival:cox artifact must be produced from an approved NHANES linked-mortality extract and explicitly approved before it can replace the surrogate. The training frame requires only age, sex, and BMI as anchors; optional blood, history, and functional values remain NaN for XGBoost's native sparsity-aware split finding — no MICE, no mean fill. The assessment MVV is still enforced before inference. A saved model is not production-ready until FRAILTY_MODEL_APPROVAL_PATH points to a hash-bound approval sidecar matching the artifact, feature manifest, reference-panel id and file hash, and reviewed uncertainty parameter. build_survival_frame also exposes cohort-level and standard sex/age-band/ethnicity-slice missing counts/rates plus event/censoring totals; fitted artifacts carry that summary as metadata. Missing ethnicity is reported as unknown. Add study-specific strata before making a validation claim; the summary is descriptive evidence, not clinical approval. Before a training run is treated as reproducible, populate and review the training-manifest template with source checksums, cycle-specific eligibility, missing-value and BIA quality decisions, linkage, survey-design limits, split strategy, sensitivity runs, and reference-panel identity. The shipped file is a template only and contains no downloaded or patient data. The API exposes nullable ci_95 fields. The shipped development path returns ci_95: null alongside uncertainty_validated: false; a numeric interval requires an approved predictor with cohort-validated uncertainty. The operator-facing startup, release, monitoring, rollback, and privacy boundary is collected in docs/OPERATIONS.md.

For release reconciliation, both health endpoints expose a safe deployment fingerprint plus the model artifact and reference-panel SHA-256 digests when files are configured. A ready runtime must expose both valid digests; development fixtures remain blocked. These values contain no API key, request body, model parameters, or patient identifier and can be copied into an operator release receipt.

Set FRAILTY_REQUIRE_PRODUCTION=true to stop startup when the model, approval sidecar, uncertainty method, reference panel, or API-key boundary is not approved/configured. The default development fixture remains runnable for local tests and this demo, but /readyz correctly returns 503.

      Gates
      
        
      Approval gates that remain
      
        
      
          Software evidence is collected. Production evidence is gated.
          The four cards below enumerate what blocks a
          "credible/production-ready" claim for any real cohort.
        
      

        
      
          
      
            E-005
            
      External, stratified cohort
      
            
      Approved CLSA/equivalent cohort, concordance index, sex/age/ethnicity subgroup metrics, and the two calibration plot artifacts (homeostatic_deviation_calibration.png, biological_age_calibration.png) produced by validate_external_cohort + write_calibration_plots.
      
          
      
          
      
            Panel
            
      Approved reference panel
      
            
      Replacement of the synthetic fixture with a versioned ReferencePanel(production_ready=True) whose tables are licensed/published SECA sources with age/sex bands, units, and provenance.
      
          
      
          
      
            Cutoffs
            
      Per-cutoff clinical review
      
            
      Documented sign-off for every ordinal threshold in fi.py:CUTOFF_SOURCES against the target population, including those annotated "validate against the target cohort before production."
      
          
      
          
      
            Cohort
            
      Approved training cohort
      
            
      An approved NHANES linked-mortality extract (or equivalent) with explicit eligibility, mortality-linkage disclosure, survey-weighting plan, and subgroup missingness report; refit of fit_xgb_survival against that cohort.
      
          
      
          
      
            Artifact
            
      Hash-bound approval
      
            
      Load the exact fitted artifact with docs/MODEL_APPROVAL.md's sidecar, bind it to the approved panel file and reviewed uncertainty method, and keep /readyz fail-closed until every field matches.
